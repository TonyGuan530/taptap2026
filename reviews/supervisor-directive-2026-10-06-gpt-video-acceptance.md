## 验收标准（用户钦定，两条）

1. **是否支撑得起 gamejam 涌现主题**（玩法是否有涌现性、主题是否立得住）

## 标准流程（所有 responded/open 的 FB、所有 3D 迁移里程碑通用）

1. **出证**：最新版的 Movie Maker 离线渲染 mp4（已有工具链）+ 若 ChatGPT 不收视频则 ffmpeg 抽 6-10 关键帧成图组。
2. **送验**：上传至本 demo 的 ChatGPT 专属对话，附固定提问模板：
   「这是 demo-NN 最新版完整游玩录像/关键帧。请按两条标准裁决：①是否支撑得起 gamejam 涌现主题？②完成度是否够玩家理解游戏机制？请给出 PASS / FAIL + 具体修改意见清单。」
3. **归档**：GPT 回复存 reviews/chatgpt-demo-NN-*-full.md + feedback-board.json 对应条目回写意见。
4. **修改**：按 GPT 意见清单逐项修改并发布新版本。
5. **复验**：修改版再走 1-2，GPT 判 PASS → FB 转 fixed（reply 注明 GPT 裁决版本）；判 FAIL → 继续修改循环。

## 制度 v2（2026-10-07 00:58 用户裁决·覆盖「双版本并存」）：3D vs 2D 对比送验，择一继续开发，败者归档

> 用户原话：「gpt反馈需递交3d2d版本 并择一继续开发 不合格的直接归档 demo只选一种呈现」。

### 送验规格（每 demo）

- **递交两份**：3D 版视频/关键帧 + 2D 版视频/关键帧（同一 demo 的两个形态，附各自版本说明）
- GPT 按两条标准（gamejam 涌现主题支撑 + 机制理解完成度）**对比裁决**

### 裁决结果（三选一）

1. **3D 胜出** → 继续开发 3D 线；2D 线归档（git 分支保留、Pages 槽位撤下、hub 只展示 3D）
2. **2D 胜出** → 继续开发 2D 线；3D 线归档（worktree/分支保留、不切 hub）
3. **都不合格** → 按 GPT 意见清单修改后重新对比送验；修改后仍 FAIL 的形态**直接归档**

### 归档语义

- git 分支/历史永久保留（可复活）；Pages 槽位与 hub 展示只保留胜者形态；败者线停止投入。
- **每 demo 最终只呈现一种形态**（用户钦定：demo 只选一种呈现）。
