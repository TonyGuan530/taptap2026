# INKBOUND：形状与词条共同授能

2026-10-07。设计提案，尚未实现；V10 与触控补丁的验收不代表本提案已完成。

用户确定方向：开放实验场，取消黑墨／黄墨用途限制；必须有合理的形状结构和相符词条才获得能力。外观像梯子不自动可攀爬，“可攀爬”本身就是词条。允许符合共同规则的奇思妙想。

## 诊断与决策

核心问题在机制与关卡结构，不能靠增加关卡、美术或随机地图修复。

| 当前代码／体验 | 对玩家创造的限制 | 改版方向 |
| --- | --- | --- |
| `sketch_rules.gd` 只接受 ladder、board、blade，各自有词条白名单 | 先选用途，才允许画；跨用途实验直接被拒绝 | 原画保留结构，通过通用能力组件判断词条是否相符 |
| `apply_drawing` 硬绑定黑墨建造、黄墨武器 | 同一画作无法跨建造、移动、战斗使用 | 第一版统一墨水；颜色可作表现或世界身份，不作功能锁 |
| Elastic 将笔迹乘以 1.4 | 有真实尺寸变化，但没有弹跳、储能等可迁移行为 | “弹性”应改变碰撞回弹；尺寸由原画决定 |
| 软藤需要 Sharp，线性高台逐个开章节 | 玩家主要猜设计者允许的道具 | 目标检查物体的位置、承重、接触和运动结果 |
| 梯子外观自动获得专用攀爬流程 | 绘画承担了词条应赋予的能力 | 无词只保留结构；可攀爬词条与合适支点共同启用攀爬 |
| 板面是 StaticBody3D | 不能搬运、推倒、压住或传递动量 | 保留旧版；新实验场采用动态画作和统一搬运接口 |

V10 的实际尺寸、真实接触、坡面支撑可以保留；它们提供局部自由，却还不足以证明涌现。两个已写好的路线只能证明多解。

## 核心循环

发现词条 → 对环境产生一个猜想 → 画出可信结构 → 用相符词条授能 → 放入世界观察 → 改画或换词再试。

三根玩法支柱：**画出可信结构、以相符词条授能、在新处境组合复用。** 物理是授能后的反馈与组合基础，不能把主旨替换成仅改变质量、恢复系数的模拟玩具。

区分三层：结构记录轮廓、长度、连接和支点；基础实体只有碰撞、重力、质量等共同规则；功能能力由词条与兼容结构共同激活。普通站立或推动属于基础碰撞，但无词画作不能主动攀爬、锋利切割或自动行动。基础规则也不能凭识别出物品名称自动加能力。

一次失败要能看出原因：“没有连续的攀爬支点”，或“有支点，但还缺可攀爬词条”。回收退还墨水，试验不消耗词条，不要求反复跑墨泉。

## 一块开放场地，先验证一个目标

首片目标：把一个实体页匣送到岛上高处邮台。纸偶邮差在水边等候，保留立体纸页美术。浅池、正面高台与侧面低坡全部从开始可见，不规定经过顺序。地图不标“这里画梯子”“这里使用漂浮”。邮台只检查页匣实际到达并稳定停留，不检查图形类别、词条、路径顺序。多张散页留待扩展，不挤入首日范围。

首轮场景包含浅水、可支撑的墙沿与高处邮台；它们根据水中负重、实际接触、支点和落脚空间响应。环境物体与画作共用接触规则。黏附接合、压板和脆弱围栏待核心体验成立再扩展。

预期可尝试：附墙攀梯、漂浮攀网、宽面浮台、固定台阶、横放原梯接回邮差。以上只是测试情景，不写成解法枚举或通关白名单。开放路线必须在真实场景中验证，不能只在文档列出。

## 最小可组合规则

首日切片仅做可攀爬、漂浮，最多两槽；黏附为下一批扩展。两词都在可直接走到的地方，首轮拾取保持稳定。后续可随机排列位置和顺序，但不能把必需资源放在对应机关之后。下表列出两批的能力边界，不能把黏附标成首日已完成。

| 词条 | 结构与环境兼容条件 | 授予的能力 |
| --- | --- | --- |
| 可攀爬 | 有连续可达支点；安装方向、有效高度和出口符合角色身体尺度 | 沿原结构攀爬。梯、绳、攀网可共享组件，但要各自具备可解释的支点 |
| 漂浮 | 有足够排水体积与承载余量；真实位于水中 | 水中产生浮力，能承受一定负重；细小画作加词也不能无限承载 |
| 黏附 | 存在真实接触面；接触面积和接合强度足够承担负载 | 将接触处固定到环境或另一实体；并不顺便授予攀爬、墙上行走 |

可攀爬＋漂浮分别保留能力，支点会随浮动结构运动；可攀爬＋黏附允许固定后攀爬；黏附＋漂浮可固定浮物或连接承载构件。结果由实际结构、接触、负载共同决定，不为每个组合编写独立通关脚本。沉重、锋利、弹性留作后续能力扩展；弹性不能只把图形放大后继续沿用这个名称。

形状至少影响轮廓、面积、质心、接触点与支点：长条易倾倒；圆轮廓容易滚；带凹口的形状可以挂住凸起；宽面有更大的承载接触区域。不能从物品名称自动授予专属功能，也不能让不相符的结构无条件激活任何词条。

画一只狗时，原画不因外观自动活过来。自己跟随、觅食等需要后续“活体／伙伴”能力与合适形态；没有词时只是原结构。首片不开发生命、武器、载具主题；后续可用有限分类或玩家确认意图辅助识别，但不让识别错误吞掉原画。

## 技术范围与复用

复用 V10 画纸、多笔保留、墨水成本、角色、美术和新的触控控制器。新场景独立保存，避免把旧版录屏与验收当成新机制的证据。

新增 `InkBody`：开放笔迹成为有限数量的胶囊段；闭合轮廓三角化后挤出为有厚度的复合凸碰撞。不能直接把现有静态凹面碰撞改成动态刚体，[Godot 官方文档](https://docs.godotengine.org/en/stable/classes/class_concavepolygonshape3d.html)也要求动态凹形物体使用复合凸碰撞。保留凹口；不得用一个包围盒代替全部形状。

首版允许平放／立放、旋转、搬运、丢下、回收；能力组件作用于同一原结构，不重画、不更换预制模型。最多六件活动画作，限制点数和碰撞片数量，先保证移动浏览器可玩。形态兼容判定与能力实施分开，不重新引入按 ladder／board／blade 物品类别允许词条的白名单。

词条组件只读取需要的结构特征与环境状态；机关只读取结果。不得出现 `if kind == boat`、`if Heavy and Triangle` 等解法开关。个别教学提示可以提问，但不能替玩家选择图形。

## 实施顺序与停止条件

1. 结构分析＋明确授能：同一梯稿无词不能爬，加入可攀爬后才可爬；不兼容结构给出具体原因。其他形态复用相同组件。
2. 动态画作、搬运与水：同一画稿换词、加第二词，肉眼能看出区别；能力不相互覆盖。黏附接合后续独立验证。
3. 邮台目标与完整回收流程：目标检测不依赖用途分类；通过三条实际玩家输入路线，至少一条将旧画作用在新处境。
4. 陌生玩家自由试验：只给目标与操作，观察自行发现的用途。若只是在按提示选词，就继续改机制与场地，停止扩地图与新主题。

验证分层：程序测试证明碰撞和物理量正确；录像证明输入能完成流程；自由试玩才用于判断惊喜和创造感。至少观察三名未看攻略的玩家，不把自动通关测试写成“已证明涌现”。

## GD 与叙事依据

采用用户指定的 [game-design-skills](https://github.com/jasonxu610/game-design-skills) 中 `game-design-100-principles` 的核心循环、主题协同、功能固着与黑盒原型测试：循环须可组合；简单独立机制应允许意料之外的用途；先检查机制是否误导玩家，而不是要求玩家理解设计者的意图。

叙事采用本地 `sw-premise-theme` 的“小、单纯、有戏核”和“主题从动作中表达”：学徒画出可信形状，用合适的词赋予能力，再发现它还能帮助谁。先用同一稿展示无能力→授能，再让它在新处境复用；三至五分钟的场景节拍允许不同顺序，不成为强制任务链。救回邮差后保留玩家原画与实际词条的小纸签，记录发生过的结果，不把它改名成标准答案。
