# 黄墨装备如何判断

这部分是后续分类设计；V10 的已批准开发范围仍为黑墨完整章与一种可挥动墨刃。弓、枪、防具未实现时不在试玩中暗示已经可用。

黄墨把候选限定为装备。识别只建议用途，原始多笔画始终保存，绘画的实际长度、轮廓和接触决定结果。玩家可以确认或改选候选，避免因为画风不同而卡关。

| 行为族 | 外形候选 | 实际行为 | 词条的作用示例 |
|---|---|---|---|
| 手持近战 | 剑、斧、锤、鞭 | 按实际画出的段和扫掠路径命中 | 锋利切断；沉重增加冲击；弹性扩大实际范围 |
| 防御 | 盾、护甲 | 盾按真实封闭面阻挡；护甲需独立穿戴规则 | 黏性留住接触物；沉重增加阻挡代价 |
| 发射 | 弓、枪 | 确认发射端和瞄准方向，发射有独立归属的画作弹丸 | 词条传给实际弹丸；不是敌人炮台的换皮 |

“锐器/钝器”适合表达接触性质，不能全靠外形来推断：一把画得像剑的东西也可以是沉重的钝剑。斧、锤不需要各复制一套战斗系统，但重量、形状、挥动方式必须造成可观察差别。枪与弓可复用投射物模块，仍需做玩家持有、发射、命中和词条传播。

## 已核对的开源选项

[$Q Super-Quick Recognizer](https://depts.washington.edu/acelab/proj/dollar/qdollar.html)公开 JavaScript 和 C# 源码，使用 New BSD 许可，支持增加自定义模板。适合将少量装备类模板作为候选匹配方案。作者的设备基准不能当作本项目的性能测试结果。

[$P Point-Cloud Recognizer](https://depts.washington.edu/acelab/proj/dollar/pdollar.html)同样公开 JavaScript/C# 源码及 New BSD 许可。点云匹配忽略笔画数、顺序和方向，适合玩家分多笔绘制同一件东西。这也意味着必须另存原笔迹的连接关系：匹配结果不能替代梯子承载或盾面闭合的真实几何判定。

它们是模板手势识别器，不自带理解所有剑斧盾枪的语义。建议用每类多种画风的模板并做真实玩家样本验证；没有样本支持的类别不要承诺识别率。

## 接入边界

1. 保留原画稿，复制一份用于识别归一化；不改变作品尺寸。
2. 墨色先筛行为类别，再按有限模板给最多三个候选。
3. 相似度作为排序，不能标成未经校准的概率。差距小或不匹配时显示“选择用途”。
4. 玩家确认一个已经实现的行为。先检查几何可用性，再计算成本并生成作品。
5. 玩家能只换用途/词条而保留笔迹。抬笔处没有隐形连接。

不需要在浏览器加载神经网络，也不需要在线识图。V10 先用明确的“梯架/板面/墨刃”用途选择，把尺寸、接触、词条和操作反馈做好；识别可在有限设备/玩家样本验证后成为输入便利层。
