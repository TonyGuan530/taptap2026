# INKBOUND GD／编剧独立评审

2026-10-07。两名独立评审分别读取本地 game-design-skills、编剧 skill、现有实现与提案。这里只记录设计结论，不代表实现或陌生玩家试玩已经完成。

## 共同结论与最终决策

主旨是：**画出可信结构，用拾到的相符词条赋予能力，再在新处境发现用途。**

- 取消黑墨／黄墨的用途限制，颜色可保留作表现。
- 形状不自动赋予功能。梯架识别成功只能证明边梁、横档和支点成立；无“可攀爬”就不能主动攀爬。
- 基础实体保留重力、碰撞、普通承重、摩擦和动量；词条提供专属能力。不能因为形状像剑就自动锋利，像狗就自动活过来。
- 能力组件检查结构特征和环境，禁止回到按物品名称规定词条的白名单。也不能让所有形状套词后都同样有效。
- 两槽能力作用于同一原画，不为每种组合写专用解题脚本。开放目标只检查真实结果。

## GD 建议

五个用于测试迁移的情景：

| 组合 | 可观察的结果与约束 |
| --- | --- |
| 梯架＋可攀爬 | 竖放或斜放登高；读取实际抓握路径与出口空间 |
| 同一梯架＋漂浮 | 横放成浮排，但不因此获得攀爬；负重与结构间隙影响稳定性 |
| 有抓握节点的藤状线／网架＋可攀爬 | 不同结构复用同一攀爬组件，必须有连通且可达的支点 |
| U 形钩架＋黏附（后续） | 抓附后拖运或吊托，依真实接触与负载判断 |
| 宽托盘＋漂浮＋黏附（后续） | 固定页匣再渡水；侧面载荷可以影响质心和姿态 |

这些情景是测试例，不是允许通关的枚举表。页匣实际进入岛上高处邮台并稳定停留就完成；支持正面高台、侧坡和浅池之间的不同运输办法。

首日只开发 **可攀爬＋漂浮、两槽、一块场地、一个目标**，保留原画、搬运／放下、平放／立放、回收与快速复位。砍随机地图、战斗、活体绘画、复杂水流、软体、破坏和压板；黏附放下一批。动态结构不稳定时先修稳定性，不扩词。

主要风险：兼容判定变成另一份物品白名单；词条对所有形状同样生效；无词垫块和承重路线过廉价，让玩家无需尝试词条。用几何、负载和稳定性形成取舍，不禁用合法捷径。

## 编剧建议

一句话经历：“我画的梯子最初只有样子；拾到可攀爬后能登高；再加入漂浮，我发现它还能接回水边的邮差。”这是体验例，不是强制剧情路线。

前三至五分钟：看见散落的信与邮差的需要 → 自己画结构 → 空词槽与失败动作展示尚无能力 → 拾词并作用到同一画稿 → 在水边把旧作品重新使用 → 邮台回应真实结果。顺序可变化，只教学操作和因果，不教学规定答案。

最多三句台词：“风把今天的信吹散了。”“样子有了，还缺一个词。”“原来，它还能接我回来。”无词作品称草稿，不提前叫攀爬梯或战斗墨刃。不兼容时指出结构缺口，例如“没有连续的攀爬支点”。

收束保留玩家原画轮廓与实际词条小纸签，记录他做过的事，不把作品改成标准浮桥或自动升级。首片只交付一个页匣目标，多页叙事和邮差救援可随核心成立后扩展。

## 依据与验收边界

GD 使用用户指定的 [game-design-skills](https://github.com/jasonxu610/game-design-skills) 中简单独立机制、主题协同、核心循环与清晰公平的谜题规则。编剧使用本地 `sw-premise-theme`、`sw-scene-craft` 与环境叙事参考，强调主题通过动作表达、同一道具在新处境改变意义。

程序与输入录像可以证明规则正确、能完成流程；只有自由试玩可用于判断是否有创造感。手机补丁保留 V10 旧玩法，不能据其通过验证宣布新设计已完成。
